## 풀이 접근

16×16 크기의 미로에서 출발점(2)으로부터 도착점(3)까지 이동할 수 있는지 판단하는 문제다.

최단 거리를 구할 필요 없이 도달 가능 여부만 확인하면 되므로 BFS를 사용했다.

- **핵심 아이디어:** 출발점부터 BFS로 상하좌우를 탐색하며 도착점에 도달할 수 있는지 확인한다.
- **자료구조:** `int[][] map`으로 미로를 저장하고, `Queue<Pos>`로 탐색할 좌표를 관리한다.
- **방문 관리:** `boolean[][] visited`를 사용하여 이미 방문한 칸을 다시 탐색하지 않도록 한다.
- **특이사항:** 벽(1)은 통과할 수 없으며, 출발점(2)과 도착점(3)은 이동 가능한 칸으로 취급한다.

**코멘트:** BFS를 통해 미로의 도달 가능 여부를 정확하게 판단했다. 다만 큐에서 좌표를 꺼낼 때 방문 처리하므로 같은 좌표가 큐에 중복 삽입될 수 있다. 큐에 넣는 시점에 방문 처리하면 불필요한 탐색과 객체 생성을 줄일 수 있다.

### 방문 처리 시점 개선

기존 코드에서는 큐에서 좌표를 꺼낸 뒤 방문 처리한다.

```java
Pos curPos = q.remove();
visited[curPos.r][curPos.c] = true;
```

이 방식은 아직 큐에서 꺼내지 않은 좌표가 여러 번 추가될 수 있다.

최적화된 코드에서는 큐에 삽입하는 순간 방문 처리한다.

```java
visited[start.r][start.c] = true;
q.offer(start);

while (!q.isEmpty()) {
    Pos cur = q.poll();

    if (cur.r == dest.r && cur.c == dest.c) {
        return true;
    }

    for (int d = 0; d < 4; d++) {
        int nr = cur.r + dr[d];
        int nc = cur.c + dc[d];

        if (nr < 0 || nr >= 16 || nc < 0 || nc >= 16)
            continue;

        if (visited[nr][nc] || map[nr][nc] == 1)
            continue;

        visited[nr][nc] = true;
        q.offer(new Pos(nr, nc));
    }
}
```

이를 통해 각 좌표가 큐에 최대 한 번만 들어가도록 보장할 수 있다.

### Union-Find와 비교

이 문제는 시작점과 도착점의 연결 여부만 판단하므로 Union-Find로도 해결할 수 있다.

격자의 각 좌표를 1차원 인덱스로 변환하고, 인접한 이동 가능 칸들을 같은 집합으로 합친 뒤 시작점과 도착점의 루트가 같은지 확인하는 방식이다.

다만 단일 경로의 도달 가능 여부를 확인하는 이번 문제에서는 BFS가 더 간단하며, 도착점을 발견하면 즉시 탐색을 종료할 수 있다는 장점이 있다.
